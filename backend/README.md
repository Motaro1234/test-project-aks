# Warehouse Stock — Test App

A minimal full-stack app to test a PostgreSQL connection and calculate stock
per warehouse. Backend is Python (FastAPI), frontend is plain HTML/JS
(no build step, easy to read and debug).

## What it does

- Tests the connection to your PostgreSQL database
- Creates two tables: `warehouses` and `stock_items`
- Lets you add warehouses and stock items (SKU, name, quantity, unit price)
- Calculates total quantity and total value **per warehouse**

## 1. Requirements

- Python 3.9+
- A running PostgreSQL server (local or remote), with an empty database created,
  e.g.:
  ```sql
  CREATE DATABASE warehouse;
  ```

## 2. Setup

```bash
cd warehouse-app
python3 -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Copy the example env file and fill in your real DB credentials:

```bash
cp .env.example .env
# then edit .env with your DB_USER, DB_PASSWORD, DB_HOST, DB_PORT, DB_NAME
```

## 3. Run

```bash
uvicorn app.main:app --reload
```

Open:
- **http://localhost:8000** — the test UI (test connection, add warehouses/stock, see totals)
- **http://localhost:8000/docs** — interactive API docs (auto-generated by FastAPI, great for debugging)

## 4. First-time use

1. Click **"Test DB connection"** — confirms the app can reach PostgreSQL.
2. Click **"Create tables (init-db)"** — creates `warehouses` and `stock_items`
   if they don't exist yet (or run `schema.sql` manually instead, if you prefer).
3. Add a warehouse, then add stock items to it.
4. The **Stock summary** table at the bottom recalculates automatically —
   this is the actual "calculate stock" logic, done with a SQL `GROUP BY`
   in `app/main.py` (`/api/stock/summary`).

## Project structure

```
warehouse-app/
├── app/
│   ├── main.py        # FastAPI routes (connection test, CRUD, summary calc)
│   ├── models.py       # SQLAlchemy table definitions
│   ├── schemas.py       # Request/response validation
│   └── database.py     # DB connection setup (reads .env)
├── static/
│   └── index.html      # Test frontend (no build tools needed)
├── schema.sql            # Plain SQL version of the tables, if you'd rather run it by hand
├── requirements.txt
└── .env.example
```

## Why FastAPI

Modern, readable Python with type hints, clear error messages, and free
interactive API docs at `/docs` — makes it easy to test each endpoint on
its own while debugging the DB connection.

## Notes / next steps you might want later

- Right now `stock_items.quantity` is a running total you edit directly.
  If you want proper stock movements (in/out transactions with an audit
  trail), that's a natural next table to add (`stock_movements`), with
  `quantity` on `stock_items` becoming a calculated sum instead of a
  stored value.
- No authentication yet — fine for local testing, but add it before
  exposing this beyond your machine.
